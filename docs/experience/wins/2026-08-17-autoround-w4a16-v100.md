# AutoRound W4A16 35B A3B on V100 (sm_70)

Date: 2026-08-17
Scope: `crates/infer-cuda/src/loader.rs`, `crates/infer-cuda/src/quant_format.rs`
Model: `LeaderboardModel1/Qwen3.6-35B-A3B-autoround-W4A16` (19.6 GB, 10 shards)
Hardware: V100-SXM2-32GB (sm_70, 32 GB VRAM, 31 GB RAM)

## Context

The 35B A3B MoE model (Qwen3.6 hybrid: GDR linear attention + full attention + 256 experts) produced degenerate output on the previous W4A16-fixed checkpoint (GPTQ fused-expert corruption, llm-compressor #2939). Switched to the AutoRound W4A16 checkpoint, which uses a different quantization method and should avoid the fused-expert bug.

Goal: run the model at high speed on a single V100 via ARLE.

## What Worked

### 1. AutoRound exports q_proj in the correct interleaved layout

The previous W4A16-fixed checkpoint stored q_proj as concatenated `[q_all(4096); gate_all(4096)]`, requiring a permutation to interleaved `[q0(256), g0(256), ...]`. AutoRound exports q_proj **already interleaved** — applying the old permutation corrupts the weights. No layout fix needed.

### 2. All GDR and shared-expert weights are quantized

AutoRound quantizes every linear layer, including GDR (`in_proj_qkv`, `in_proj_z`, `in_proj_a`, `in_proj_b`, `out_proj`) and `shared_expert` (`gate_proj`, `up_proj`, `down_proj`). A loader that only dequantizes attention q/k/v/o_proj and experts leaves GDR weights as meta tensors → all-NaN logits from layer 0.

### 3. ARLE GPTQ W4A16 path produces NaN for non-expert weights

ARLE's `load_gptq_w4a16_view` + sm_70 W4A16 GEMV kernel works for expert weights but produces NaN for GDR and shared-expert weights. Root cause unconfirmed (suspect: kernel edge case on small-N matrices like `in_proj_a`/`in_proj_b` at N=32, or the recurrent-scan GDR forward path not handling W4A16 dequant correctly).

**Workaround**: dequantize all non-expert GPTQ weights to BF16 in a checkpoint-prep step; keep experts in GPTQ format (ARLE loads them natively). Cost: +2 GB VRAM (21 GB checkpoint, 30 GB loaded) vs 19 GB for the all-GPTQ path. Fits in 32 GB.

### 4. ARLE needs `quantization_config` in config.json

ARLE's `read_quant_manifest` reads `quantization_config` from `config.json` only. AutoRound stores quant metadata in `quantize_config.json` (empty in this export) and omits the field from `config.json`. Without it, `quant_manifest` is `None` and `quant_view_for` returns `None` for every tensor — GPTQ detection is disabled entirely. Adding `{"quant_method": "autoround", "format": "gptq", "group_size": 128, "bits": 4}` to `config.json` enables it.

### 5. Model prefix and classification

- AutoRound uses `model.` prefix; ARLE hardcodes `model.language_model.` → rename in checkpoint prep.
- `model_type: "qwen3_5_moe_text"` doesn't match ARLE's `"qwen3_5"` / `"qwen3_5_moe"` match, but `arch_contains("Qwen3_5")` matches `Qwen3_5MoeForCausalLM` → correct Qwen35 loader routing.

### Decode speed

Measured via OpenAI-compatible server, two requests (greedy, short prompts):

| Prompt tokens | Decode tokens | Wall time | Derived decode | Derived TTFT |
|---------------|---------------|-----------|----------------|--------------|
| 22 | 50 | 2.31 s | — | — |
| ~15 | 200 | 7.66 s | — | — |

Solving `t = n/r + p` from the two points: **decode ≈ 28 tok/s, TTFT ≈ 0.53 s**.

The PyTorch fallback (flash-linear-attention absent, eager MoE loop) ran at 0.7 tok/s — ARLE's native CUDA path is **40× faster** on the same hardware.

## Rule

- AutoRound and llm-compressor export different q_proj layouts — never assume the permutation fix from one checkpoint applies to another; verify against the modeling code's `.view(..., head_dim*2).chunk(2)` contract.
- When a quantized model NaNs, check every quantized layer class, not just the attention projections — GDR and shared-expert linears are quantized too.
- ARLE's GPTQ detection is gated on `quantization_config` in `config.json`; a checkpoint without it silently loads all weights as dense BF16 (or fails on missing `.weight` keys).
