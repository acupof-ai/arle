# V100 (sm_70) BF16 GEMM — FP16-cast path fixes cudaErrorNotSupported prefill

**Date:** 2026-07-14. **Backend:** CUDA, legacy Volta (sm_70, V100-SXM2-32GB).
**Scope:** `crates/cuda-kernels/csrc/gemm/gemv.cu` — BF16 GEMM dispatch.
**Status: verified 2026-07-14** — end-to-end serve + chat on the V100 box
(sm_70 test lane) with `Qwen3.5-0.8B`: HTTP 200, 50 completion tokens, no
`CUDA_ERROR_NOT_SUPPORTED`, no errors/panics in serve log. The layer-3 full
attention prefill step that previously faulted now passes.

## Context

The V100 new-user flow errored on the first inference step (prefill) at
layer-3 full attention with `CUDA_ERROR_NOT_SUPPORTED`. V100/Volta (sm_70)
has **no BF16 tensor cores and no BF16 cuBLAS compute at all** — only
FP16/FP32. A BF16 `cublasGemmEx` / `cublasLtMatmul` faults at runtime with
`cudaErrorNotSupported`, and the fault is **asynchronous** (the API returns
SUCCESS, surfacing only at the next stream sync), so a post-hoc retry cannot
catch it without a per-call `cudaStreamSynchronize`.

## What Worked

Gated exclusively on `device_compute_major() <= 7`, leaving the sm_80+ hot
path byte-identical:

- **`gemm_cublaslt_impl`** — on sm_70 skips cublasLt entirely (its heuristic
  selects a BF16 tensor-core algo that faults) and routes to
  `gemm_cublas_fallback`. Skipping cublasLt also avoids caching a bad algo.
- **`gemm_cublas_fallback`** — on sm_70 calls `gemm_fp16_cast_cuda`: cast
  the BF16 operands to FP16, run an FP16 tensor-core GEMM (V100 has FP16
  tensor cores), cast the FP16 result back to BF16. Allocates per-call
  scratch — this is the legacy Volta-only path, never the sm_80+ hot path.
- **`device_compute_major`** — cached per device ordinal (a single
  `cudaGetDeviceProperties` at first use) so the uncached per-step lookup
  that caused a −77% decode regression (2026-06-12) does not return.
- Added a NOT_SUPPORTED `cublasGemmEx` retry with `CUBLAS_GEMM_DEFAULT`
  (CUDA-core math, correct on every device) as a defensive second tier.

## Rule

- **Asynchronous GEMM faults need a static dispatch gate, not a retry.** A
  fault that surfaces only at the next sync can't be caught per-call without
  a global sync; detect the hardware class once (compute major) and route
  around the bad path.
- **Per-device cache the capability probe.** An uncached
  `cudaGetDeviceProperties` per layer per step is a −77% decode regression.
- **sm_80+ hot path must stay byte-identical.** All Volta logic gates on
  `device_compute_major() <= 7`; the FP16-cast path is never reached on
  sm_80+.
