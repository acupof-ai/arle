# Qwen3.6-35B-A3B FP8 + MTP on H20 — CUDA, 2026-07-16

> Status: Shipped

## Goal

Validate Qwen3.6-35B-A3B (FP8 MoE, hybrid linear+full attention) inference on a single H20 GPU, with and without MTP speculative decode, measuring decode throughput at c=1,4,8 concurrency.

## Hypothesis

The 35B-A3B hybrid MoE (30 linear-attention + 10 full-attention layers, 256 experts, 8/tok) should decode faster than the 27B dense model at the same FP8 quant level, due to the linear-attention layers being cheaper than full attention. MTP (2 draft tokens, greedy topk=1 verification) should provide a modest speedup.

## Parameters

```
Model: Qwen/Qwen3.6-35B-A3B-FP8 (35 GB, FP8)
Backend: CUDA, single GPU (no TP)
MTP: --spec-type mtp --mtp-draft-tokens 2 --mtp-draft-topk 1
Prompt: "Explain quantum computing in simple terms."
Max tokens: 200 per request
Trials: 3 per concurrency level
```

- Baseline: no MTP (greedy decode only)
- Treatment: MTP with 2 draft tokens, greedy verification (topk=1)

## Environment

- Host: 8×H20 box (180 cores, 1.9 TB RAM)
- GPU: 1× NVIDIA H20 (96 GB), CUDA 12.9
- Model: Qwen3.6-35B-A3B-FP8, FP8 quantized, 35 GB
- TP/EP: 1/1 (single GPU)
- KV: BF16, 116930 pages @ page_size=16, 38.3 GB for 10 full-attn layers
- Server flags: `--port 8800 --bind 0.0.0.0`

## Problems

- DeepGEMM MoE native bridge unavailable (CUDA_ERROR_NOT_SUPPORTED on H20); falls back to hand-grouped kernels — functional but not optimal.
- TP=2 requires NCCL feature which is not compiled in this binary; single GPU used (35 GB model fits in 96 GB with room for KV cache).
- MTP improvement is minimal at greedy topk=1 (0.5–1.7%); higher draft token counts and topk would increase the speedup but was not tested.

## Learnings

PASS. The 35B-A3B FP8 model runs correctly on a single H20 GPU with MTP speculative decode. The hybrid MoE architecture delivers ~2× the decode throughput of the 27B dense model at the same quant level. MTP with greedy verification provides a small but consistent speedup. Next wall: enable DeepGEMM native for H20 to close the MoE kernel gap, and test higher MTP draft token counts for larger speedups.
