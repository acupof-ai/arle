# The 2-GPU CP training ceiling moved 114,688 → 131,072, and the binding point moved with it — 2026-08-20

Commits: `28a1a79ef` (linear-attention core sub-group), `62b4927b8` (transport
chain residency drops), on top of `31fd41531` (block permute) and `6b98c8cc9`
(buffer sizing, in-place residual).

## Context

Target is 256K on 2 GPUs. `--synthetic-writeback-seq N --cp-size 2`,
ThinkingCap-Qwen3.6-27B-FP8, LoRA r16 α32 attention-qv, 2×H20 (97,508 MiB).
cp=2 means local seq = N/2, and the ceiling is per-rank: cp=4 at global 229,376
and cp=2 at global 114,688 both bind at local 57,344.

## Result

| global seq (cp=2) | local | before | after |
|---|---:|---|---|
| 114,688 | 57,344 | pass, 90,971 MiB | pass, 91,990 MiB |
| **131,072** | 65,536 | **OOM** (`cuda allocation failed in transpose`, 1.4 GB) | **pass**, `ckpt-peak actual` 75,875 MiB, 331 s |
| 163,840 | 81,920 | OOM in **forward** at 185 s | forward + fused CE complete; OOM in **backward** |

**The ceiling is 131,072, up from 114,688.**

Matched points, same local seq, same `floor` and `layer` model terms:

| local | | `actual` | `drift` |
|---|---|---:|---:|
| 65,536 | before (cp=4 @262144) | 81,383 | +19,907 |
| 65,536 | after | 75,875 | +14,252 |
| 81,920 | before sub-group + drops | 84,789 | +17,420 |
| 81,920 | after | **77,026** | **+9,657** |

Loss is bit-identical across the sub-group change at the rung where both
complete (5.538711 at cp=2 seq=65536), which is what "only the free schedule
changed" should look like.

## What worked

**A checkpoint group is one whole layer, so the peak is that layer's sum over
stages.** `ops/checkpoint.rs:118` groups one layer and `:41` frees nothing until
its backward finishes. Wrapping the gated-delta core in its own `checkpoint`
splits the replay: the core's intermediates are freed when its own backward
completes rather than at the end of the layer. It is inert in the forward —
`checkpoint` passes straight through while `!tape.enabled`, which is the state
the outer group's forward runs in — and engages only in the backward, where
`checkpoint_backward` replays on a fresh `Tape::new()` (enabled, offload off).

**Then the forward became the binding side, and it was transients, not
residency.** The 163,840 profile showed driver `used` jumping 47,291 → 80,539
MiB across a single layer while live bytes moved 41,863 → 43,465 — a ~33 GiB
transient spike inside one group. `slice`, `all_to_all`, `cat` and
`permute_seq_blocks` save shape metadata only, and none of their backwards reads
the input's value, so each stage's input is value-dead the moment the next
returns; it just stays resident because the group frees once at the end.
Dropping residency at each stage took 7,763 MiB off the pool high-water at local
81,920 and halved the model's drift.

## The measurement lesson

The sub-group change was first measured at cp=2 local 32,768, where `actual` did
not move **at all** — 58,047 before and after, to the digit. It looked inert.
It is not: at that rung the high-water is set by the FORWARD (floor 39,279 plus
a forward live set of about 20,656), and the change only affects the backward.
The rungs that actually fail near the ceiling fail in the backward
(`la dqkv`, `slice_bwd`), which is where the change pays.

**A change that only affects one phase has to be measured where that phase
binds.** Measured comfortably below the ceiling, it reads as a no-op — and a
false no-op costs more than no measurement, because it retires a lever that
works.

## Also fixed

`Backend::upload` ignores the shape it is passed, so a tensor whose device
residency was dropped and then re-fetched would have produced a zero-length
handle carrying a full-size shape, and the next kernel would have read past it.
`ensure_device` now refuses empty host data for a non-empty shape. That failure
mode existed before this change; it just had no reachable caller.

## Where it binds now

163,840 fails in the backward on `zeros [1, 81920, 5120]`, 1.6 GB. The next
levers from the bf16 audit are both backward-side and bit-exact: fusing the
three `slice_backward` scatters into one destination (8,960 MiB at local
131,072) and recomputing `preact` in the conv backward instead of taping it
(4,480 MiB).

bf16 is not among them. The audit refuted 45 of 47 candidate conversions: three
f32 chokepoints (`cuda_slice` hard-errors on a bf16 handle, `f32_operand`
widens instead of accepting, and the NCCL transport is f32-typed) turn every
bf16 store on this path into either an error or a net increase, and there is no
per-tensor dtype selector to express one with. Separately,
`backend_cuda/kernels/linear_attention.cu` uses 434 bare `float`s and none of
the `T` alias the bf16 NVRTC module defines, so selecting that module returns an
f32 kernel that writes 4 bytes per element into a u16 buffer without erroring —
a latent heap overrun behind a flag nobody currently sets.

## Rule

Measure a phase-specific change where that phase binds. And when a checkpoint
group frees only at its boundary, the group boundary is a memory knob: every
stage inside it pays for every other stage's peak.
