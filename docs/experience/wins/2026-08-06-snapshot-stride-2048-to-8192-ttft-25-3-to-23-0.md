# Snapshot stride 2048 → 8192: 33K TTFT 25.3 → 23.0 s — 2026-08-06

> Status: **Confirmed, default flipped.** `SIDECAR_SNAPSHOT_STRIDE_PAGES`
> 128 → 512. Costs cross-conversation restore granularity, buys 9.2% of TTFT.

## Context

After the pinned-staging entry showed the 18 prefill stalls were host time and
not the D2H, the remaining question was what the host does at each stride
boundary. The answer is in the shape of the data, not the copy:

Every periodic snapshot retains a full recurrent-state copy until publish —
27B has 48 linear layers × (48 v-heads × 128 × 128) f32 = **3.0 MB per layer,
~150 MB per snapshot**. A 33K prefill at a 2048-token stride takes 18 of them
and holds **2.7 GB** live simultaneously. Nothing is freed mid-prefill, so
none of it can be recycled — the allocation is genuinely new memory every time.

Measured rate: 2.7 GB in 3.13 s = **0.86 GB/s**, far under a host memcpy. The
cost is allocation and first touch, and it scales with snapshot count.

## What worked

A probe first, not a fix: stride raised past the prompt so zero periodic
snapshots fire. GPU 6, `iso-tc-huihui-w8a16`, `bench-agent-32k-64.jsonl`, c=1,
16 requests × 256 tokens, seed 20260416, two reps per arm.

| stride | snapshots at 33K | TTFT p50 | ITL p50 |
|---|---:|---:|---:|
| 2048 tok (`128` pages) | 18 | 25.29 / 25.35 s | 16.70 / 16.68 ms |
| 8192 tok (`512` pages) | 4 | **22.96 / 23.06 s** | 16.70 / 16.69 ms |
| none (probe, `4096` pages) | 0 | 22.18 / 22.18 s | 16.70 / 16.69 ms |

Reps agree to 0.10 s. The three arms are linear in snapshot count — 18 → 3.13 s,
4 → 0.85 s, 0 → 0 — which is the mechanism's own prediction and the reason the
shipped stride is 512 rather than the probe's.

ITL is untouched at every arm: this is a prefill-only cost.

Against SGLang on the same weights and kernel (21.03 s), TTFT goes from 1.19×
to **1.09×**.

Correctness license: needle ladder 512/4096/16384/32768, three runs, all
`exact=3 partial=0 miss=0 DET` — 12/12. The gate needs the thinking-model
flags (`TEMPLATE=qwen3_nonthink RAW=1 NEEDLE_MAX_TOKENS=512`); without them it
reports all-miss on an empty `content` and reads as a kernel fault.

## The tradeoff, stated

The periodic snapshot exists so a LATER conversation sharing only a leading
prefix can restore mid-prompt instead of re-prefilling. Widening the stride
does not remove the feature; it caps how much such a request must re-prefill at
8K tokens instead of 2K. Nothing else changes — `L*` (the within-conversation
exact-resend boundary) is untouched.

What is still unmeasured: the cross-conversation hit rate. The old stride
charged 12.4% of every cold 33K TTFT unconditionally for a benefit that only
lands on a hit. 8192 charges 3.6%. Whether even that is earned needs a hit-rate
measurement this entry does not have.

## Rule

When a per-event cost is a full retained copy of state, the lever is the event
count, not the transfer. Look at what the operation *keeps*, not only what it
moves: 2.7 GB held live across one prefill cannot be pooled, recycled, or
overlapped away — only made rarer or smaller.
