# DSv4 M=1 GEMV: 1.8× isolated (ncu-proven) but WALL-NEUTRAL — the kernel is overlapped

## Context

Chasing decode-6ms, the synced `stage_profile` showed `mla_attn`=12ms/token as the
dominant decode stage → I isolated the M=1 FP8 GEMV, ncu-profiled it (memory-LATENCY-bound,
long_scoreboard=16.6), and landed a **uint4-vectorized weight load** (16 FP8/load vs 16
single-byte loads). Microbench: **60.4→33.8µs, a real 1.8× (ncu: dram 5.7→11.2%)**,
byte-identical output.

## What the wall A/B showed

Built it into the full TP=8 decode, needle B=1 SPEC=0: output **byte-identical** but
**steady_tok_s 38.16 ≈ baseline 38.5 — WALL-NEUTRAL** (1.8× GEMV → 0% decode). Reverted
(bench-win rule: wall-neutral ≠ ship).

## Root cause / Rule

- **The M=1 GEMV is OVERLAPPED in the async pipeline — it's not on the decode critical
  path.** A 1.8× isolated kernel speedup buys nothing at the wall because the GPU was
  already hiding that kernel behind other work. Same class as the decode-graph/mHC/
  comm-overlap washes, one level deeper.
- **The synced `stage_profile` MISLEADS for the wall.** It calls `stop.synchronize()` per
  stage, so it reports each stage's *isolated* time (mla_attn 12ms) — which INFLATES
  overlapped stages and does NOT reveal the critical path. The earlier "mla_attn 12ms =
  the lever" conclusion was an artifact of synced profiling.
- **B=1 decode is CRITICAL-PATH-bound**, not per-stage-kernel-bound. The wall is the serial
  per-layer dependency chain (attn → all-reduce → MoE → next layer) × 43 layers. The ONLY
  lever that moved B=1 this whole investigation was MTP (it amortizes the WHOLE critical
  path over ~1.85 tokens) — because per-kernel opts are all overlapped/washed.
- **To find the actual decode-wall lever, use nsys (the timeline + gaps), NOT the synced
  stage_profile.** The 6ms path is shortening the critical path (fuse per-layer kernels to
  cut serial launches+dependencies, faster all-reduce) — SGLang's mega-kernel approach — an
  architectural kernel effort, not a per-op optimization.
- License every decode-perf change on a WALL-CLOCK same-binary A/B; an isolated-kernel or
  synced-stage number is necessary-but-NOT-sufficient (this is the 4th confirmation:
  graph, mHC, comm-overlap, now GEMV).
