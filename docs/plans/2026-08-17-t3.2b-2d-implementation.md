# T3.2b — 2D KV ownership sharding: implementation design

> Status: implementation plan (2026-08-17). Companion to
> `2026-08-16-cp-ideal-state.md` §T3.2b. Decisions pinned by code exploration
> (workflow wf_203c8aac-00d, 2026-08-17). Industry survey: vLLM #26133/#46358,
> SGLang #21637, Megatron CP.

## Pinned decisions

1. **Shard function = page-granularity block-cyclic: logical page `i` → shard
   `i % cp`.** Contiguous sharding migrates page ownership as seq_len grows (a
   paged pool cannot survive this). Block-cyclic is stable under growth,
   load-balances the newest page round-robin, and — since `block_size ==
   page_size` (radix.rs:3-5) — **block `B` always lives on shard `B % cp`**: a
   pure function. This collapses the location table to zero storage.
2. **The pool stays dumb; the shard filter lives in the host allocator +
   executor.** Production Qwen-dense is mirror-mode: `HostPagedKvPool` is the
   single allocator, `TokenKVPool::mirror_slot` is a dumb 1:1 id mirror that
   bypasses `free_pages`/`page_attach_count`. The device pool needs no shard
   field — only its *sizing* changes (1/cp). The host pool gains a `ShardSpec`
   and filters `alloc`/`append_pages_needed`.
3. **`seq_len` stays rank-identical (lockstep); only page ownership diverges.**
   Every rank accounts the same token lengths and row shapes; the shard changes
   *which physical pages* back those lengths, never the lengths themselves.
4. **2D engage predicate = `attn_tp ≥ 2 && cp ≥ 2` (world ≥ 4), replacing the
   per-chunk length threshold** for prefill. Decode keeps a length floor
   (re-tune `CP_DECODE_MIN_KV_TOKENS`).
5. **Prefix cache is staged, not in the big-bang critical path.** B+D+E ship
   with prefix cache *disabled under 2D* (no publish, no attach for 2D
   requests — the ring pass recomputes the whole prompt). Part C flips it back
   on with replicated radix. The attach filter (3-line modulo guard) lands
   with B as a safety net so a stale radix hit degrades to recompute, not
   corruption.

## Architecture in one paragraph

Rank (t, c) — attn_tp shard t, cp shard c — holds attn_tp shard t's heads for
cp sequence shard c. Full-attention KV is double-sharded (head by attn_tp,
sequence by cp); GDN recurrent state is attn_tp-sharded, cp-replicated;
weights are attn_tp-sharded (unchanged). The host pool (`HostPagedKvPool`,
infer-seam) becomes cp-aware: a slot's page table on rank c holds only shard
c's logical pages, where logical page `i` maps to shard `i % cp` (block-cyclic,
stable under sequence growth). The engine's page budgeting scales by the
executor's `kv_shard_factor()` (cp_size under 2D, else 1). Prefill is one ring
pass over the whole prompt (T1 ring core). Decode is 2D flash-decoding: FA3
split-KV over the local shard, cross-cp (lse, out) merge on comm_stream, then
global all-reduce across attn_tp.

## The load-bearing invariant

**Every rank's `slot_pages[slot]` holds exactly one cp shard's pages (logical
page `i` on shard `i % cp`), and the engine's page accounting is scaled by
`kv_shard_factor()`.** Everything else follows. The engine stays device-neutral:
it queries a capability, never the mesh. The pool stays the single owner of
page→shard mapping (a pure function of the logical page index, no per-block
location table).

## Phase B — Pool sequence-sharding

### B.1 `infer-seam/src/host_paged_kv_pool.rs`
- Add `ShardSpec { cp_size, cp_rank }` (default 1, 0) + `set_cp_shard(..)`.
- **Block-cyclic (pinned decision 1)**: logical page `i` → shard `i % cp`.
  `alloc(slot, tokens)` appends global logical pages; the slot keeps only those
  with `i % cp == cp_rank`. Stable under growth (no ownership migration) and
  the location is a pure function. `slot_pages[slot][j]` = physical page for
  global page `cp_rank + j·cp`.
- `append_pages_needed(slot, tokens)`: cp-aware — count local pages among the
  new global pages (`ceil(new_global / cp)` rounded).
- `page_indices_for_token_range(slot, len)`: cp-aware — return the strided local
  subset covering `[0, len)` (local page `j` kept iff `(cp_rank + j·cp)·page_size < len`).
- `attach_pages(slot, pages, token_count)`: `pages` is the local shard's block
  ids (filtered by `B % cp == cp_rank`). Attach only those.
- `truncate_slot(slot, new_len)`: drop local pages past `new_len`.
- `free_slot(slot)`: unchanged (frees the local shard's pages).
- The executor derives token positions from the block-cyclic mapping (global
  page `cp_rank + j·cp` → token range), so no new position query is needed.

### B.2 `infer-seam/src/lib.rs` (BackendExecutor)
- Add `fn kv_shard_factor(&self) -> usize { 1 }` (default; CUDA returns
  `attn_cp_size` when the 2D mode is engaged, else 1).

### B.3 `infer-core/src/prefix.rs`
- `request_pages_needed_after_prefix` (line 16): scale `token_pages` by
  `self.executor.kv_shard_factor()` — `token_pages = token_pages.div_ceil(shard)`
  ... actually `token_pages / shard` rounded: each rank holds 1/shard the pages.
  Keep the fixed-band arm unchanged (DSv4 is not a 2D candidate).

### B.4 `cuda-kernels/src/paged_kv.rs` (TokenKVPool)
- No structural change. Storage is already per-rank
  `[max_total_pages, num_kv_heads, page_size, head_dim]`; under 2D each rank's
  pool simply holds fewer pages per slot (1/cp). `max_total_pages` is sized from
  HBM (unchanged) — the capacity win is more slots per rank, not a bigger pool.
- The executor's KV write/read paths use the local page table (B.1) — they
  already index by physical page id, so writing shard c's KV to shard c's pages
  is a matter of passing the local page table + the shard's token range.

### B.5 Engine↔executor page-table contract
- `KvQuery::page_indices(slot)` returns the LOCAL shard's pages (B.1). The
  executor's prefill/decode kernels already take a page table; under 2D the
  table is the local shard's, and the kernel is told the shard's token range
  (positions are absolute — T1's position arrays handle this).

## Phase C — Radix replicated across cp + location table

### C.1 The problem
Prefix match is from-start; a per-rank partial radix cannot match (rank c has
no block 0). Industry gap (vLLM/SGLang both leave CP prefix cache unsolved).

### C.2 Design
- The radix block→page mapping is **replicated across cp**: every cp rank holds
  the full token tree, but each block's page lives on exactly one shard.
- **Location = `B % cp`** (zero storage): since `block_size == page_size`
  (radix.rs:3-5), block `B` always lives on shard `B % cp`. No per-block
  location table, no collective exchange of locations.
- `infer-core/src/radix.rs`: the radix tree becomes replicated — every cp rank
  holds the full token tree, but `Node.page_id` is `Some` only on the owning
  shard, `None` elsewhere. `publish_prefix_blocks` (prefix.rs:335) seals only
  the local shard's blocks, then all-gathers the published block *tokens* across
  cp so every rank inserts the full token set (content-addressed → identical
  tree on all ranks).
- Residency is per-shard: block B is resident iff rank `B % cp`'s page is live.
  The T3.2a min-reduce aligns the matched length across cp ranks — a missing
  block on any shard truncates the match for all.
- `KvPrefixStore::attach_pages` receives the LOCAL shard's block ids (filtered
  by `B % cp == local_rank` in `attach_prefix_restore`, prefix.rs:181).

### C.3 Prefill reuse disabled initially
Under Option A the ring pass recomputes the whole prompt; the radix match is
not used to skip prefill KV. The location table + attach path serve **decode
reuse** (multi-turn: a follow-up attaches the prior turn's sharded pages and
decodes via phase E). Gathering the paged cached-prefix shard into the ring
block is a follow-up.

## Phase D — Ring prefill (single pass)

### D.1 Replace `cp_share_chunk_kv` (qwen35_attention.rs:1088)
- The T2 replicated gather (stage k/v → all-gather → re-run prep per peer →
  write to local pool) is replaced by one ring pass over the whole prompt.
- Rank c computes its q-shard (prompt/cp contiguous rows) and KV shard. The KV
  shard is ring-rotated (P2P send/recv over the attn_cp comm, cp-1 hops). At
  each hop, rank c runs T1's `ring_block_fwd_merge_fa3` on the received K/V
  block against its q-shard, accumulating (m,l,out). After cp-1 hops, rank c
  has attended to all shards.
- Rank c writes ONLY its shard's KV to its pool (B.1 local page table).
- Positions are absolute (T1's `q_pos`/`k_pos` arrays) — contiguous shards
  under Option A, so the causal mask is the standard lower-triangular per
  (q_shard, k_block) pair. Zigzag is a future optimization (ring core already
  supports it via position arrays); start contiguous (rank 0 never stalls,
  rank cp-1 carries more attention — measure before adding zigzag).
- GDN relay unchanged (qwen35_attention.rs:1341): the recurrent state is
  cp-replicated, relayed alongside the ring. The ring handles full-attention
  KV; the GDN relay is a separate per-layer state chain.

### D.2 Comm
- Ring rotation on the attn_cp sub-comm (NCCL send/recv). Reuse the T2 relay's
  comm pattern. The KV block per hop is one shard's K/V for one layer
  (`[prompt/cp, kv_dim]` bf16) — at 256K, cp=2, that's ~1.6 GB/layer/hop,
  overlapped with the FA3 compute on the previous hop's block.

### D.3 No chunking
Under 2D the whole prompt is one ring pass. The engine must NOT chunk a 2D
request's prefill — the planner emits one prefill row spanning the prompt.
Guard: 2D mode + chunked prefill = reject at admission (or the planner emits a
single row). Activation memory is layer-by-layer (serving), so one pass is
memory-safe; the cost is loss of decode-interleaving/preemption for 2D
requests (accepted in the Option A decision).

## Phase E — Flash-decoding decode merge

### E.1 The decode step (rank (t,c))
1. FA3 split-KV over the LOCAL shard's KV (the local page table, B.1):
   `paged_attention_quantized_fa3` (BF16 path, qwen35_attention.rs:739+) runs
   UNCHANGED — it keeps intra-rank split-KV and outputs `(lse, attn_out)` where
   `lse = m + ln(l)` and `attn_out` is the NORMALIZED partial output for the
   local shard.
2. All-gather `(lse, attn_out)` across the cp group (small:
   `[batch·heads]` lse + `[batch·heads, head_dim]` out per layer, fp32 lse).
3. A new local merge kernel combines the cp partials. **No FA3 modification
   and no unnormalized-partial exposure needed**: the cross-cp merge is the
   flash-decoding weighted average
   `out = Σ_r w_r·out_r / Σ_r w_r`, `w_r = exp(lse_r − max_r lse_r)`.
   This is exactly correct: the full-shard attention is
   `[Σ_r out_r·exp(lse_r−m)] / [Σ_r exp(lse_r−m)]` with `m = max_r m_r`, and
   the ratio is invariant to the max choice (a constant shift cancels in
   numerator/denominator), so `max(lse_r)` — which we have — substitutes for
   `max(m_r)` — which we don't. SGLang #21637's "LSE-weighted combine" is the
   same formula.
4. Global all-reduce across attn_tp (the existing `all_reduce_sum`) combines
   head-shards into the hidden state.

### E.2 New merge kernel (cuda-kernels)
- `cross_cp_merge` (small, one threadblock per batch·head): input `[cp,
  batch·heads]` lse (fp32) + `[cp, batch·heads, head_dim]` out (bf16), output
  `[batch·heads, head_dim]`. Compute `m = max(lse)`, `w = exp(lse − m)`,
  `out = Σ w·out / Σ w`. This is the SGLang "separate local combine kernel"
  shape — not fused into FA3.
- Gated: built only under the 2D mode (world≥4). B2 (world=2) is untouched.

### E.3 comm_stream
- The all-gather + merge run on `comm_stream` (tensor.rs:182, unused by
  collectives today) with compute↔comm fences (tensor.rs:637): the FA3 output
  (compute stream) must be visible before the all-gather (comm stream), and
  the merged output must be visible before the downstream GEMM (compute
  stream). The `all_reduce_sum_on(.., Comm)` plumbing (tp.rs, in flight on
  another branch) is the template.

### E.4 GDN decode
- attn_tp-sharded, cp-replicated. Rank (t,c) advances its attn_tp shard t's
  GDN state (replicated across c — redundant, but GDN compute is small). No
  cross-cp merge for GDN. The B2 two-buffer decode pair (T3.1) extends: the
  decode pair is per (t, c) but identical across c (replicated).

## Resolved open points (2026-08-17 exploration)

1. **Page-table indexing under 2D** — RESOLVED. Block-cyclic `i % cp` with
   local-indexed page tables. `mirror_host_slot`'s full-coverage check
   (qwen35.rs:235) is recomputed against the shard-local page count. The 1:1
   host↔device id contract holds because one budget solve feeds both pools
   (qwen35.rs:704-711) with the same cp-divided page count.
2. **Ring P2P vs NCCL** — RESOLVED. Reuse the attn_cp P2P primitives
   (`attn_cp_send`/`attn_cp_recv`, tp.rs:761/798) on comm_stream. `k_pos` rides
   the ring with each KV block (or derives from `(owner_rank, page_idx)` since
   `i % cp` is invertible).
3. **FA3 partial (m,l,out) exposure** — RESOLVED. FA3's BF16 decode path
   already outputs `(lse, attn_out_normalized)`. The cross-cp merge is the
   flash-decoding weighted average `Σ w·out / Σ w`, `w = exp(lse − max lse)`,
   which is exactly correct (invariant to the max choice). No FA3 change.
4. **GDN state under 2D prefill** — RESOLVED. GDN relay unchanged (serial chain,
   cp-1 sequential hops/layer). Under a single full-prompt ring pass this chain
   is on the critical path for every linear layer — accepted for v1, flagged
   for a later overlap optimization.
5. **2D mode engage condition** — RESOLVED. `world ≥ 4 && attn_tp ≥ 2 && cp ≥ 2`
   replacing the per-chunk length threshold for prefill. Decode keeps a length
   floor (re-tune `CP_DECODE_MIN_KV_TOKENS` from a measured c-sweep; do not
   carry 8192 forward). Inherits bf16-only, no-recall, no-spec mutexes.

## Implementation order

1. **Part B** (pool sharding) — serial, the foundation. `ShardSpec`, host pool
   alloc filter, executor budget divisor, `mirror_host_slot` fix, scheduler
   token→page audit. Includes the Part C attach filter as a safety net.
2. **Part D** (ring prefill) and **Part E** (decode merge) — parallel after B.
   D: dense-prep kernel split + ring pass + finalize caller. E: sharded meta +
   owner-conditional write + merge kernel + quant-lane OOB fix.
3. **Part C** (radix replication) — parallel with D/E (host-side, independent
   of device work).
4. **Integrate + gate** — world≥4 predicate, needle ladder ×3 at world=4
   (attn_tp=2, cp=2) vs the world=2 B2 / world=4 attn_tp=4 envelope, 256K
   capacity at world=4, decode no-regression vs B2, dated wins entry.

The `i % cp` predicate must be single-sourced (one helper in `infer-seam` next
to `ShardSpec`) used by B's alloc, D's pool write, E's meta/owner-write, and
C's attach filter — or the exactly-once ownership invariant breaks.
